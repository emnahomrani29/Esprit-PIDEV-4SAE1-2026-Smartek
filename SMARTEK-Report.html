1. Executive Summary

SMARTEK is an intelligent web platform developed at ESPRIT (PIDEV 4SAE1, 2025–2026) for managing learning paths, skill development, professional certifications and career matching. It unites Learners, Trainers, HR personnel, Administrators and Partners in a single ecosystem built on Spring Boot 3.2 microservices, an Angular 18 front-end, a MySQL database layer, JWT-based security and a complete DevOps pipeline.

This report documents the full project advancement: Sprint 0 (analysis and foundations), Sprint 1 (Module 1 of every axis — core microservices and infrastructure), Sprint 2 (Module 2 of every axis — advanced features, security and automated testing), and Sprint 3 (DevOps, CI/CD, Kubernetes deployment and observability).

By the end of Sprint 3, SMARTEK runs as a production-shaped platform on a local Kubernetes cluster with automated Jenkins pipelines, SonarQube quality gates, Nexus artefact storage, Docker Hub image registry, Trivy vulnerability scanning, Cosign image signing and Prometheus/Grafana observability.

Key figures at the end of the project:

  • 13 microservices (10 Spring Boot business services + API Gateway + Config Server + Eureka) orchestrated on Kubernetes.
  • 13 Jenkins pipelines automating detect-changes, build, test, scan, publish and deploy across the monorepo.
  • Docker images on Docker Hub (wafachabbi/*) and versioned Maven artefacts on Nexus.
  • Prometheus + Grafana observability with alerting rules for service-down, high memory and high error rate.
  • Angular 18 front-end with Tailwind CSS, 6 role modules, feature-complete across all functional axes.
  • Trivy image scanning and Cosign image signing for supply-chain security on every pipeline.

2. Project Context and Scope

2.1 Vision and Motivation

The modern professional landscape demands continuous upskilling, yet existing platforms are fragmented — learning management systems ignore career matching, skill-tracking tools lack certification workflows, and HR platforms rarely integrate training analytics or exam management.

SMARTEK unifies these needs into a single platform combining learning path management, skill evidence collection, course delivery, training programs, exam management, job offer matching, event planning, professional certification and community engagement.

4.4 Identity and Security Foundation

Sprint 1 introduced the end-to-end authentication flow still in use: the auth-service issues JWT access tokens (24-hour expiration); the Angular SPA routes through the Gateway (port 8090), which validates the JWT and enforces RBAC; downstream services trust the pre-validated JWT via a shared JwtAuthFilter registered before UsernamePasswordAuthenticationFilter.

Roles (LEARNER, ADMIN, TRAINER, RH_COMPANY, RH_SMARTEK, PARTNER) are defined in the auth-service RoleType enum and embedded in the JWT claims (username, userId, role). All services share the same JWT secret key, enabling stateless cross-service token validation without a central identity provider.

By the end of Sprint 1 the Angular 18 application skeleton was initialised with standalone components and Tailwind CSS. The front-end successfully performed its first authenticated CRUD flows through the Gateway (login → token acquisition → routed request to auth-service), proving that the Frontend → Gateway → Microservice chain was functional before Sprint 2 advanced development began.

5.4 Security Hardening (JWT, RBAC)

  • Gateway validates every JWT and enforces route-level RBAC before forwarding requests.
  • All downstream services register a JwtAuthFilter as a Spring Security filter chain, enabling method-level security (@EnableMethodSecurity).
  • Session management set to STATELESS across all services — no server-side session state.
  • CSRF disabled (stateless JWT architecture); CORS configured per service with allowed origins for the Angular client.
  • Actuator endpoints (/actuator/**) permitted without authentication for Prometheus scraping and Kubernetes health probes.
  • Analytics endpoints in skill-evidence-service permitted without authentication for public dashboard access.
  • Passwords hashed with BCrypt; JWT secret shared across services via Config Server.

6. Sprint 3 — DevOps, CI/CD, Cloud Deployment & Monitoring

Sprint 3 industrialised the SMARTEK platform: every Spring Boot microservice and the Angular front-end are now built, scanned for code quality, scanned for vulnerabilities, signed, published and deployed automatically by Jenkins pipelines targeting a Kubernetes cluster. This section describes the architecture that was put in place, the per-service pipelines, the registry strategy and the monitoring stack.

6.1 CI/CD Architecture Overview

The CI/CD topology promotes the Sprint 2 monorepo without any architectural rewrite. A push to the repository triggers Jenkins polling; each pipeline uses a smart change-detection stage that analyses git diff --name-only HEAD~1 HEAD and skips the pipeline entirely if no files in the service's folder were modified, so unaffected services finish in seconds. Every pipeline reuses the same multi-stage skeleton:

  • Stage 1 — Detect Changes: Git diff analysis; skip if no changes in service folder (unless branch is main/develop).
  • Stage 2 — Build: mvn clean package -DskipTests — fast compilation and packaging.
  • Stage 3 — Test: mvn test with JUnit XML report published to Jenkins.
  • Stage 4 — SonarQube Analysis: mvn sonar:sonar with project key, host URL and token; quality gate enforced.
  • Stage 5 — Push to Nexus: mvn deploy with ad-hoc settings.xml using nexus-creds; snapshots stored at http://192.168.100.138:8089/repository/maven-snapshots/.
  • Stage 6 — Docker Build: docker build producing two tags — :BUILD_NUMBER and :latest.
  • Stage 7 — Trivy Scan: trivy image --severity HIGH,CRITICAL — vulnerability scan on the built image.
  • Stage 8 — Docker Push: Push both tags to Docker Hub (wafachabbi/<service>).
  • Stage 9 — Sign Docker Image: cosign sign --key cosign.key — supply-chain security via image signing.
  • Stage 10 — Deploy to Kubernetes: kubectl apply + kubectl set image + kubectl rollout status --timeout=10m.
  • Stage 11 — Smoke Test: HTTP health check via curl against the NodePort endpoint.
  • Stage 12 — Verify Prometheus: Query Prometheus API to confirm metrics scraping is active for the deployed service.

6.4 Pipeline Stages in Detail

6.4.1 Build & Test stage (Maven + JUnit)

Each Spring Boot Jenkinsfile invokes Maven to run mvn clean package -DskipTests for the build stage, followed by mvn test for the test stage. JUnit XML reports are published to Jenkins via the junit step with allowEmptyResults: true to prevent pipeline failure on services with no tests yet. The compiled artefact is available for the subsequent Docker build stage.

6.4.2 SonarQube Analysis stage

All services share the SonarQube instance at http://192.168.100.138:9000, each with its own project key matching the service name. The analysis is invoked via mvn sonar:sonar with the project key, host URL and authentication token passed as system properties. The stage uses catchError(buildResult: 'SUCCESS', stageResult: 'UNSTABLE') so a quality gate warning does not block deployment.

6.4.5 Image Signing with Cosign

After the Docker push, each pipeline signs the image using Cosign with a local key pair (/home/wafa/cosign.key). The signing command is cosign sign --key cosign.key --yes docker.io/wafachabbi/<service>:BUILD_NUMBER. This provides supply-chain security guarantees — consumers can verify the image was produced by the authorised Jenkins pipeline and has not been tampered with. The stage uses || true to prevent pipeline failure if the signing infrastructure is temporarily unavailable.

6.4.6 Deploy stage & Smoke Test

The Deploy stage applies the Kubernetes namespace manifest, then applies the service-specific deployment YAML and updates the running image via kubectl set image deployment/<service> <service>=wafachabbi/<service>:BUILD_NUMBER -n smartek. It then waits for the rollout to complete with a 10-minute timeout (kubectl rollout status deployment/<service> -n smartek --timeout=10m).

The Smoke Test stage waits 60 seconds for the service to start, then performs an HTTP health check via curl against the NodePort endpoint. A 200 response confirms the service is up; any other status is logged as a warning without failing the pipeline.

6.4.7 Frontend pipeline specifics

The frontend pipeline deviates from the Spring Boot template: the build runs npm install followed by npm run build --prod to produce an optimised Angular build. 7.3 Cross-Cutting Capabilities

  • Container orchestration: Kubernetes cluster (Docker Desktop / Minikube / cloud-ready), Flannel CNI, MetalLB, nginx-ingress, 24 K8s manifests managed by Kustomize, bash and PowerShell deployment scripts.
  • CI/CD & quality: 14 Jenkins pipelines with per-service folder watching, SonarQube quality gates, JUnit test reporting, Nexus artefact storage and Docker Hub image registry.
  • Supply-chain security: Trivy vulnerability scanning (HIGH/CRITICAL) on every Docker image; Cosign image signing on every pipeline run.
  • Observability: Prometheus scraping all 11 services via /actuator/prometheus; Grafana dashboards for CPU, memory, HTTP rates and error rates; Alertmanager with ServiceDown, HighMemoryUsage and HighErrorRate rules.
  • Security: JWT stateless authentication shared across all services; BCrypt password hashing; RBAC with 6 roles; CORS configured per service; Actuator endpoints public for health probes.
  • Inter-service communication: OpenFeign synchronous calls for data enrichment; internal API key for exam → certification badge trigger; Eureka-based load balancing via the Gateway.
  • Testing: JUnit 5 + Mockito unit tests; Spring Boot Test + MockMvc integration tests; Postman collections per service; SonarQube quality gate.
  • Frontend: Angular 18 with Tailwind CSS, 6 role modules, NGINX reverse proxy, optimised production build with asset hashing and gzip compression.
  • File management: PDF upload (50 MB max) in course-service with UUID-based naming; Cloudinary integration for profile pictures in auth-service.
  • Email notifications: Mailtrap SMTP integration in certification-badge-service for certificate delivery; configurable SMTP credentials via application.yml.

8. Conclusion

SMARTEK is a complete engineering deliverable. Sprint 0 produced the analytical foundations; Sprint 1 delivered Module 1 of every axis — 10 Spring Boot microservices with MySQL persistence, Eureka discovery, API Gateway routing and JWT security; Sprint 2 added Module 2 (advanced features, OpenFeign inter-service communication, Spring Security method-level RBAC, automated testing and certification badge issuance); Sprint 3 industrialised the platform with Jenkins CI/CD, Kubernetes deployment, SonarQube quality gates, Nexus artefact storage, Docker Hub image registry, Trivy vulnerability scanning, Cosign image signing and Prometheus/Grafana observability.

The platform covers every SAE layer: distributed back-end, secured gateway, CI/CD, container orchestration, supply-chain security, observability and a feature-complete Angular 18 front-end with six role modules. Remaining work is incremental — multi-node HA cluster, static domain with TLS certificate, and expanding test coverage to 80%+ across all services — rather than foundational. SMARTEK is ready for end-to-end demonstration.
